# Контракт: бинарный формат словаря анаграмайзера (v1)

Общий контракт между **генератором** (Python/Swift-скрипт, Track A) и **движком-ридером** (Swift, Track B).
Обе стороны ОБЯЗАНЫ следовать этому документу побайтно. Любое изменение формата → bump `version` и правка обеих сторон.

## Принципы
- **Little-endian** для всех многобайтовых чисел.
- Всё, что нужно для запросов, лежит на диске; движок только mmap-ит и сканирует. Никаких больших in-memory индексов (резидент — единицы МБ).
- Слова НЕ хранятся как строки — только коды букв (1 байт/буква).

## Алфавит (фиксированный)
33 буквы русского алфавита, код = позиция:
```
а=0 б=1 в=2 г=3 д=4 е=5 ё=6 ж=7 з=8 и=9 й=10 к=11 л=12 м=13 н=14 о=15 п=16
р=17 с=18 т=19 у=20 ф=21 х=22 ц=23 ч=24 ш=25 щ=26 ъ=27 ы=28 ь=29 э=30 ю=31 я=32
```
Коды 0..32. Значения 33..255 недопустимы в словах.

## ё/е
- Флаг заголовка `flags` bit0 = `yoFolded`:
  - `0` → «ё» сохранена как отдельный код 6 (слова содержат код 6, если были с ё).
  - `1` → «ё» свёрнута в «е» (код 5) при генерации; код 6 в словах не встречается.
- Решение по умолчанию для v1: **сохранять ё (yoFolded=0)**; опция «ё=е» реализуется на стороне движка при запросе (нормализация запроса+словаря к коду 5 на лету). Генератор фиксирует фактический выбор в отчёте.

## Раскладка файла (по порядку)

### 1. Header (16 байт)
| Смещение | Тип | Поле | Значение |
|---|---|---|---|
| 0 | 4×u8 | magic | `A N G R` = 0x41 0x4E 0x47 0x52 |
| 4 | u16 | version | 1 |
| 6 | u16 | flags | bit0=yoFolded, остальные 0 |
| 8 | u32 | wordCount (N) | общее число слов |
| 12 | u8 | maxLen | макс. длина слова (в буквах), ≤ 40 |
| 13 | 3×u8 | reserved | 0 |

### 2. Length table (сразу после header)
Для каждой длины L от 1 до maxLen включительно — запись 8 байт:
| Тип | Поле |
|---|---|
| u32 | offset — смещение начала bucket'а длины L, **относительно начала WordBlock** (секция 3) |
| u32 | count — число слов длины L |

Размер таблицы = `maxLen * 8` байт. Длины без слов имеют count=0 (offset допускается любой, обычно = offset следующего непустого).

### 3. WordBlock (сразу после length table; здесь начинается отсчёт offset из секции 2)
Слова, сгруппированные по длине в порядке L=1..maxLen. Внутри одного bucket'а:
- каждое слово = ровно L байт (коды букв 0..32), без разделителей;
- слова отсортированы **лексикографически по кодам букв** по возрастанию (для потенциального бинарного поиска и детерминизма);
- дубликаты внутри bucket'а недопустимы (генератор дедуплицирует).

Итого размер WordBlock = Σ (L × count[L]).

## Что делает движок с этим форматом
- **Шаблонный поиск** (`к_т`): взять bucket нужной длины, сканировать, сопоставлять маску позиций (джокер = любой код).
- **Анаграммы/подслова из букв**: перебрать bucket'ы длины ≤ |входной набор|, для каждого слова проверить multiset-вложенность кодов входного набора (с учётом джокера/бланка как wildcard-кода). Length-pruning + ранний отсев. Latency не является бюджетом — скан приемлем.
- Анаграммная сигнатура (сортированный мультимножество кодов) вычисляется на лету из L байт слова; отдельный on-disk индекс в v1 НЕ требуется (держим формат простым, память минимальной).

## Валидация формата (обязательна для обеих сторон)
- Round-trip тест: генератор пишет → ридер читает → случайная выборка слов декодируется обратно в кириллицу и сверяется с исходным списком.
- Проверка magic/version при загрузке; несовпадение → error-state, не краш.
- Границы: все offset/count в пределах файла; иначе error-state.
